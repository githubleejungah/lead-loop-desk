# 데이터 설계

> 상태: 승인(사용자 "승인, 코드로", 2026-11-25) · 구현 반영 · 근거: [requirements.md](requirements.md) · [architecture.md](architecture.md)
> 데이터는 모두 가상이다. 이름 · 전화번호는 지어낸 값이고, 번호는 실제로 쓰이지 않는 `010-0000-` 앞자리만 쓴다.

## 1. 정본 표

| 데이터 | 정본 | 주인(바꿀 수 있는 쪽) | 사본 |
|---|---|---|---|
| 가상 치과 · 매체 3개 · 매체별 광고비 | `data/seed.js`의 `advertiser` · `media` | 없음(파일 고정, AS-09) | 광고주 깔때기 · 단가 표 |
| 리드 40건의 시작 상태 | `seed.leads` | 없음(AS-14) | store 메모리의 처음 값 |
| 결번 목록 · 템플릿 3개 · 시연 기준 시각 · 매체 조건 | `seed.invalidNumbers` · `templates` · `DEMO_NOW` · `mediaRules` | 없음 | 판정 · 메신저 · 타이머 · 대기열 |
| **현재 리드 상태**(단계 · 끝 상태 · 부재 · 첫 응대 · 넘기기 · 정정 · 기록 · 보냄) | store 메모리(새로고침하면 시작 상태로) | 상담원(행동 버튼) | 두 화면 모든 숫자(읽기만) |
| 결번 · 중복 판정 결과 | store 메모리. 시작 때 `leads.judge()`가 한 번 정함 | 판정 규칙 | 리드 목록 · 깔때기 · 대기열 |
| 기본 손잡이 9개 · 허용 범위 | `seed.defaultKnobs` · `knobRanges` | 없음(AS-01~07 · AS-15 · AS-16) | store 처음 값 · 입력 검사 |
| **현재 손잡이 9개** | localStorage `lld:v1:knobs` (저장이 막히면 store 메모리) | 대행사 담당자(계산기 입력 · 되돌리기) | 연 매출 4줄 · 합계 |
| 깔때기 · 단가 · 응답 시간 구간 · 대기열 · 해시 · 연 매출 | 저장 안 함. 매번 계산 | core 규칙 | 두 화면 |

- 저장되는 것은 손잡이 9개뿐이다. 리드 상태는 저장하지 않는다(ADR 0002).

## 2. 구조

### 2-1. 리드 한 건 (store 메모리)

| 칸 | 값 | 규칙 |

| `phone` | `010-0000-0001` 꼴 | 상담원 화면은 `010-****-0001`(AC-03). 광고주 화면에는 넘기지 않음(AC-02) |
| `createdAt` | 에포크 밀리초(DEMO_NOW 기준 몇 분 전) | 28일 · 90일 · 타이머 계산. 다른 시각 칸도 같은 형식 |
| `clickAt` | Google만, ISO 시각 | 클릭 뒤 90일(AC-27). 시작 데이터는 모두 리드 생성과 같은 시각 |
| `consent` | 참 · 거짓 | '광고 성과 개선 활용'(선택) 동의. 40건 중 30건 참(AS-12) |
| `stage` | 0 새 리드 · 1 연결 · 2 예약 · 3 내원 · 4 계약 | 앞으로만 1칸씩(AC-08). 끝 상태가 돼도 지워지지 않음 → "연결 이상" 같은 셈에 씀 |
| `end` | 없음 · `absent_closed` 부재 종료 · `not_self` 본인 아님 · `declined` 상담 거절 · `invalid` 결번 · `duplicate` 중복 | 끝 상태면 진행 버튼 0개(AC-12) |
| `absentCount` | 0~4 | 부재 표시 횟수. 4가 되면 `absent_closed`(5절 확인 사항) |
| `nextCallAt` | 없음 · ISO | 부재 1 → 당일(+2시간) · 2 → 다음 날 10:00 · 3 → 3일 뒤 10:00 (AS-10) |
| `firstResponseAt` | 없음 · ISO | 상담원이 처음으로 연결 · 부재 · 템플릿 · 끝 상태 표시 중 하나를 한 시각 |
| `owner` · `handedOffAt` | `A` · `B`, 없음 · ISO | 넘기기는 1번(AC-20). 넘긴 뒤 타이머는 `handedOffAt`부터 다시 1시간 |
| `corrected` | 참 · 거짓 | 정정 1번(AC-10 · AC-11) |
| `log` | `[{at, text}]` | 상태 · 메시지 · 정정 사유 · 보냄 기록. 사유는 1~100자 |
| `sentAt` | 없음 · ISO | '보냄(모의)' 기록(AC-30) |

### 2-3. 손잡이 9개 · localStorage `lld:v1:knobs`

| 칸 | 기본값 | 허용 범위(정수) | 근거 |
|---|---|---|---|
| `soloFee` 단독 월 요금(원) | 300,000 | 0~5,000,000 | AS-01 |
| `linkFee` 연동 월 요금(원) | 200,000 | 0~5,000,000 | AS-02 |
| `soloCount` 단독 고객 수 | 50 | 0~10,000 | AS-03 |
| `convPct` 대행 전환율(%) | 10 | 0~100 | AS-04 |
| `adSpend` 월 광고비(원) | 10,000,000 | 0~1,000,000,000 | AS-05 |
| `feePct` 수수료율(%) | 15 | 0~100 | AS-06 |
| `agencyCount` 대행 고객 수 | 20 | 0~10,000 | AS-07 |
| `extraMonths` 늘어난 유지 개월 | 3 | 0~60 | AS-07 |
| `linkCount` 연동 고객 수 | 10 | 0~10,000 | AS-15 |

```json
{ "v": 1, "soloFee": 300000, "linkFee": 200000, "soloCount": 50, "convPct": 10, "adSpend": 10000000, "feePct": 15, "agencyCount": 20, "extraMonths": 3, "linkCount": 10 }
```

- 읽을 때 9칸 모두 허용 범위 안의 정수가 아니거나 `v`가 1이 아니면 통째로 버리고 기본값을 쓴다.
- 읽기 · 쓰기가 예외를 내면 메모리에만 두고 안내 1줄을 켠다(AC-51).

### 3-1. 되돌리기 번호 정규화 · 해시

| 매체 | 정규화(해시 전) | 예 |
|---|---|---|
| Google | `+82` + 맨 앞 0을 뺀 숫자 | `010-0000-0001` → `+821000000001` |
| Meta | 국가 번호를 붙인 숫자만 | `821000000001` |

- 해시는 SHA-256, 소문자 16진수 64자. 화면에는 앞 12자 + `…` 를 보이고 원래 번호는 보이지 않는다(AC-29).
- 정규화 규칙은 매체 도움말 기준으로 만든 예시다. 실제 연동 때 매체 최신 문서로 다시 확인한다(I).

## 5. 설계하며 정한 것 · 확인할 것

- **부재 횟수(설계 승인 때 정함):** 요구 A3에 맞춰 첫 통화 부재(1) → 당일 재연락 부재(2) → 다음 날 재연락 부재(3) → 3일 뒤 재연락 부재(4) → 부재 종료. AC-16 · 17을 그에 맞게 고쳤다(requirements 3-3).
- **부재는 연결 전(새 리드)에서만** 표시한다. 연결 뒤 연락이 끊긴 경우는 이번 범위 밖(I).
- **TikTok 되돌리기:** 요구는 Meta · Google 조건만 다뤘다. TikTok은 대기열에 "연동 조건 조사 전 — 리포트용으로만"을 보이고 보내기 버튼을 두지 않는다(I).
- **정정:** 진행 단계는 바로 전 단계로, 사람이 표시한 끝 상태(부재 종료 · 본인 아님 · 상담 거절)는 끝 상태를 지운다. 자동 판정(결번 · 중복)은 정정하지 않는다.
- **90일 가림:** 시작 데이터는 모두 31일 안이라 화면에는 나오지 않는다. 단위 시험으로만 확인한다(AC-31).

## 6. 구현하며 알게 된 점 (2026-11-25)

- 시각 칸은 ISO 글자 대신 에포크 밀리초 숫자로 두었다. 빼기 계산이 단순하고 시험이 시각대에 흔들리지 않는다. 화면 표시는 `ui/html.js`가 한국 시간으로 바꾼다.
- 응답 시간 구간은 '응대 대기' 2건(M01 · T06)을 뺀 33건으로 센다. 시연 사례 1에서 M01을 응대하면 '1시간 안'이 23 → 24건이 되고 내원율이 26% → 29%로 바뀐다(브라우저 확인).
- 한국어 조사: 매체 이름 뒤 '가/이'를 매체별로 정했다(Meta가 · Google이 · TikTok이).
